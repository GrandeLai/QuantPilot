## 正文内容

### 10.1 美股合规

#### 10.1.1 PDT（Pattern Day Trader）规则

FINRA 规则下，如果你在 **保证金账户** 中的 5 个交易日内完成 4 次或更多日内交易，且这些日内交易占总交易量比例超过一定阈值，通常会被认定为 **Pattern Day Trader**。  
此时账户需要维持至少 **$25,000** 的最低净值，否则会受到日内交易限制。

这条规则会直接影响很多“高频日内美股策略”的现实可行性：

- 小资金账户即使策略逻辑成立，也可能因为账户规则无法执行
- 现金账户与保证金账户的限制不同

#### 10.1.2 SEC 监管要点

对个人量化交易者最需要知道的，不是把法规背下来，而是理解以下原则：

- 经纪账户和证券交易行为受美国证券监管体系约束
- 交易记录、报税、结算和客户资产保护都有明确规则
- 某些策略行为在纸面上可行，但在账户制度、结算制度或经纪商风控下不可行

对个人开发者的实用建议是：

- 做美股策略前，先搞清账户类型、交易权限、结算周期和融券限制
- 不要只看开源代码示例，要看你将使用的券商实际支持什么

#### 10.1.3 券商选择建议

##### Interactive Brokers（IBKR）

- 覆盖全球市场，专业度高
- 接口成熟，适合多资产研究与执行
- 学习曲线较高，但上限也高

##### Alpaca

- API 友好，适合程序化接入
- Paper Trading 支持较方便
- 对纯开发者非常友好

##### TD Ameritrade / Schwab / thinkorswim 路径

很多旧教程会提 `TD Ameritrade API`。需要注意：

- **截至 2024 年 5 月，Charles Schwab 已完成 TD Ameritrade 客户迁移与整合**
- 因此今天再看到 “TD Ameritrade” 时，应更多理解为 **Schwab / thinkorswim 继承路线**

也就是说，旧教程不一定完全失效，但要先确认 API、账户和平台是否已迁移到 Schwab 体系。

### 10.2 加密货币合规

#### 10.2.1 不同地区监管差异

加密货币监管的最大特征是：  
**地区差异极大，而且变化快。**

同一个交易所、同一种产品，在不同地区可能有完全不同的可用性：

- 某些地区允许现货，不允许高杠杆合约
- 某些地区允许交易，但要求更严格 KYC
- 某些地区对稳定币、衍生品、托管有额外限制

所以做加密量化时，永远不要默认：

> 只要 API 文档写了，这个功能我就一定能在我的账户和地区使用。

#### 10.2.2 KYC/AML 要求

- **KYC（Know Your Customer）**：身份认证
- **AML（Anti-Money Laundering）**：反洗钱

它们影响的不是抽象合规，而是非常具体的账户能力：

- 提币限额
- 杠杆权限
- 子账户功能
- 大额资金冻结审查

#### 10.2.3 交易所风险

加密世界还要额外考虑：

- 平台暴雷
- 提币冻结
- 链上拥堵
- 稳定币脱锚

所以加密量化不仅是“策略风险管理”，也是“平台信用与资产托管风险管理”。

### 10.3 税务基础

#### 10.3.1 美股税务

个人量化交易者至少要知道：

- 长期资本利得税 vs 短期资本利得税通常税率不同
- 券商会提供如 `1099` 等税务文件
- 高频交易会让你的税务记录和成本核算复杂度上升

工程上，这意味着你最好：

- 保留完整成交记录
- 能按策略、账户、资产导出交易历史

#### 10.3.2 加密货币税务

各国差异非常大，但共同点通常是：

- 交易、兑换、某些 staking/收益场景可能产生税务后果
- 如果没有清晰的成本基准记录，后续申报会很痛苦

#### 10.3.3 专业建议

> 税务问题不要靠论坛截图做最终判断，实盘前最好咨询合格税务顾问。

### 10.4 安全实践

#### 10.4.1 API Key 管理

错误做法：

- 硬编码到代码仓库
- 发给机器人或截图给别人
- 在多个脚本里复制黏贴

推荐做法：

- 环境变量
- `.env`（仅本地，不入库）
- HashiCorp Vault / 1Password / 系统 keychain

#### 10.4.2 IP 白名单

如果交易所支持：

- 为 API Key 绑定固定出口 IP

这样就算密钥泄露，攻击者也未必能直接调用。

#### 10.4.3 提币白名单

对加密账户尤其重要：

- 只允许提到预先登记的钱包地址

这是防止“账户被攻破后资金瞬间转走”的最后防线之一。

#### 10.4.4 2FA / U2F

- 2FA：双因素认证
- U2F / 硬件安全密钥：更强的登录保护

不要把短信验证码当成万能解法。  
对高价值账户，硬件密钥更可靠。

#### 10.4.5 冷热钱包分离

对加密账户，常见做法是：

- **热钱包**：放运行策略所需的小额资金
- **冷钱包**：放大部分长期资金

不要把所有资产都长期挂在高频可访问的热环境里。

### 10.5 实盘上线 Checklist

下面这份清单建议你在每次准备上线真实策略前逐项勾选：

- [ ] 数据源已验证：时间戳、复权、扩展时段、盘口口径均明确
- [ ] 回测已加入手续费、滑点与基本流动性约束
- [ ] 样本外验证和 Walk-Forward 结果已检查
- [ ] Paper Trading 连续运行稳定，能处理断线与重连
- [ ] OMS 支持幂等下单、撤单和状态恢复
- [ ] 风控规则已覆盖单笔风险、日亏损、最大持仓、熔断
- [ ] 监控与告警已接通，异常可被及时发现
- [ ] API Key 未硬编码，已启用权限最小化和 IP 白名单
- [ ] 加密账户已开启提币白名单、2FA/U2F
- [ ] 账户权限、地区限制、杠杆规则已人工确认
- [ ] 税务记录导出与留存方案已准备
- [ ] 已准备人工紧急停机流程
- [ ] 第一阶段实盘资金规模已刻意压小

## ⚠️ 常见误区与易混淆点

1. **“策略逻辑没问题，合规和税务以后再说。”**  
   错。很多策略在账户规则或税务成本下根本不值得做。

2. **“API Key 放本地仓库没关系，反正是私人项目。”**  
   错。私人项目一样会泄露，尤其当你同步、备份或分享代码时。

3. **“交易所支持某接口，就表示我所在地区也能用。”**  
   错。账户与地区限制经常是分层的。

4. **“Paper Trading 表现稳定，就可以上大资金。”**  
   错。实盘应该从极小资金开始，逐步放量。

5. **“安全只要开个 2FA 就够了。”**  
   错。权限、白名单、资金分层、紧急处置同样重要。
